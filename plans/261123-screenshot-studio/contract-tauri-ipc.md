# Contract: Rust <-> UI (Tauri 2 IPC)

Owner: plan author. Version 1. Transcribed by phase 1.1 into `crates/ss-core/src/contract/ipc.rs`; TS types are
GENERATED by ts-rs 12 into `crates/ss-core/bindings/` (UI imports them via the Vite/TS alias `@bindings/*`).
Never hand-write a TS type that mirrors a Rust one.

## Global rules

1. **Command call shape:** every command takes exactly one argument named `req` (a struct) or none. The ONE
   exception is `save_edited_image`, which takes a raw binary body (`tauri::ipc::Request`, PNG bytes) plus headers; it
   is listed in `RAW_BODY_COMMANDS` in `src/lib/ipc.ts` and excluded from the `req`-wrapping test by that list.
   JS: `invoke<T>('query_images', { req })`. Rust: `async fn query_images(req: ImageQuery, state: State<'_, AppState>) -> Result<ImagePage, AppError>`.
   (Avoids Tauri's camelCase->snake_case argument-name conversion entirely.)
2. **Casing:** all struct fields camelCase on the wire (`#[serde(rename_all = "camelCase")]`, ts-rs follows serde).
   Enum variants are camelCase string literals (`#[serde(rename_all = "camelCase")]`), e.g. `"cloudOnly"`.
   Command names and event names are snake_case / kebab-case as listed below.
3. **Integers:** EVERY integer field (ids, ms timestamps, byte sizes, counts) is Rust `i64` and carries an explicit
   ts override, because `#[ts(type = ...)]` replaces the whole field type: `i64` -> `#[ts(type = "number")]`,
   `Option<i64>` -> `#[ts(type = "number | null")]`, `Vec<i64>` -> `#[ts(type = "number[]")]`. All values < 2^53.
   Without it ts-rs emits `bigint` while serde_json emits a number. `contract_test.rs` FAILS if any generated `.ts`
   file contains `bigint`. No type aliases for ids: a job id is the field `jobId: number` of `JobStarted { jobId }`.
4. **Optional:** `Option<T>` is serialized as `null` (never omitted): `#[serde(default)]` on input, no `skip_serializing_if`.
   ts-rs emits `T | null`. Input structs accept a missing optional key as `null`.
5. **Error envelope:** every command returns `Result<T, AppError>`; the rejected promise value is
   `{ "kind": ErrorKind, "message": string, "detail": string | null }`.
   `ErrorKind` = `"notFound" | "io" | "db" | "invalidArgument" | "conflict" | "sidecarUnavailable" | "cancelled" | "permissionDenied" | "protectedRoot" | "confirmationRequired" | "internal"`.
   `message` is human-readable English; the UI maps `kind` to an i18n string and shows `message` as detail.
6. **Long jobs** return `JobStarted { jobId }` immediately and report through events; cancel with `cancel_job`.
7. **Every mutation of files or of image-level organization** (move, copy, rename, trash, restore, recycle, tag/untag,
   favourite, rating, note, album add/remove/reorder, edit overwrite, convert) returns `OpResult` and writes one
   `op_journal` batch, undoable. `delete_permanently` is journaled as `purge`, `undoable: false`. Catalog-only
   container deletions (`remove_library_root`, `delete_tag`, `delete_album`, `delete_smart_filter`) and renames of
   tags/albums are NOT journaled and NOT undoable: the UI shows a confirm dialog naming what is lost (tags/notes/album
   membership of N images); they never touch files.
8. **Caller and protected roots:** every `ss-core` write API takes `caller: Caller` (`Ui | Cli`). A file write whose
   source OR destination path lies under any `protectedRoot` path (or any path containing `\OneDrive\`) is allowed only
   for `Caller::Ui` (the Tauri commands) and is always journaled; `Caller::Cli` (`ssctl`) gets `protectedRoot`.
9. **Cloud-only files:** background passes (index, thumbnails, AI) never open a `cloudOnly` file. An explicit user action
   on one image (open full size, edit, export, copy, convert) may open it; OneDrive then downloads it on demand, as
   Explorer does. Nothing ever pins, unpins or sets file attributes.

## Image URLs (`ssimg` async custom scheme, D5)

- Built in the UI ONLY by `src/lib/ssimg.ts`: `convertFileSrc('thumb/' + id + '/' + w, 'ssimg')` and `convertFileSrc('full/' + id, 'ssimg')`
  (on Windows these resolve to `http://ssimg.localhost/thumb/<id>/<w>` and `http://ssimg.localhost/full/<id>`).
- `w` is `320` or `1280` only; anything else -> 400. Unknown id -> 404. Thumbnail not yet generated -> 202 with an
  empty body and header `x-thumb-state: pending|offline` (UI shows a shimmer placeholder and listens for `library-changed`).
- Cache: `Cache-Control: max-age=31536000, immutable` with the URL suffix `?v=<mtimeMs>` added by `ssimg.ts`.
- CSP: `img-src 'self' http://ssimg.localhost ssimg: data: blob:`.

`core:default`, `dialog:default`, `clipboard-manager:allow-write-text`, `clipboard-manager:allow-write-image`,
`opener:allow-reveal-item-in-dir`, `opener:allow-open-path`, `notification:default`, `global-shortcut:allow-register`,

Capability `windows`: `["main", "tray-recent"]` (the tray popup window of 4.1 is created at runtime with
`WebviewWindowBuilder`, label `tray-recent`; no `tauri.conf.json` window entry). Drag-out (4.2): `drag:default`
from `tauri-plugin-drag`.
`fs:*` is NOT granted to the webview (all file work goes through commands). No `shell:*`.
